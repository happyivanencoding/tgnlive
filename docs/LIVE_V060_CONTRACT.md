## Shared backend/frontend interface

- GET /api/worlds -> {worlds:[...]} includes authored AND persisted user-created worlds. Each world: existing id,title,subtitle,description,powers[{id,name,description}], plus genre:string, tags:string[], sourceLabel:string (plain label, originals or explicitly unofficial fan-inspired), powerSystem:{summary:string,realms:[{name,rank,benchmark?}],growth:string}, optional createdAt. Frontend handles existing v0.5 worlds without these additions during development. Do not show hidden future story plans.
- POST /api/worlds/custom JSON {prompt:string,requestId:string}. One bounded real ACP world-creation request, SSE response same framing as turns: stage {name,status?,elapsedMs}, complete {world,metrics}, error {message,code,retryable}. There is no fake streaming prose or percent progress for a structured world result. On success show a review/select-power/start panel, not an automatic extra generation. Cancel via AbortController; backend observes disconnect before committing. Repeating completed requestId returns the persisted world and prevents duplicate generation. Validation errors before stream use normal JSON HTTP status.
- POST /api/games {name,worldId,powerId} retains contract. Game embeds/saves the full world authority as a snapshot so later preset edits do not retcon its canon; existing games use original definition. Realm progression, seed facts/NPCs/coins/items, opening, powers are world-specific, no universal cinder-river lore in new worlds. Public game includes reader-safe world/power-system information if needed, no hidden plans.
- All current turn/resume/export/metrics/cancel endpoints remain functional. Extra `state.currencyName` allowed; default 铜钱. Three suggestions plus free action preserved. Completion means canonical commit, previews can fail/cancel.
