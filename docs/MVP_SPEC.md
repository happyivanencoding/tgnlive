## Product
A playable Chinese progression-fantasy novel. Create an adult protagonist (name), choose one of three genuinely different asymmetric powers with concrete limits, enter one authored opening world. 3 suggested actions + free-text action each turn. The world accepts refusal, aggression, escape, bargaining, and unusual feasible actions without forcing all roads back to one quest. Impossible wishes/claims are attempts, NOT authority to change state. NPCs have their own immediate desires; spatial orientation, meaningful consequences, early payoff and readable power identity matter. Approximately 300–800 Chinese characters per normal scene, natural dialogue, not robotic fragments or authorial self-justification. Simple vocabulary; no terms for ordinary objects.

Persistent player realm/progress, money, important items, location, goals, relationships, revealed facts and promises. Show readable realm identity, not merely a number. Durable event/canon ledger in SQLite; chat prose is not the database. Chapter grouping every 6 accepted turns (configurable within source 5–10 range), library/resume, read-as-novel mode, Markdown/text export. Never commit partial/failed/cancelled generation. Idempotent request IDs and optimistic versions prevent double rewards.

## Architecture
Use the actual installed Node 24 runtime. Prefer a single local Node HTTP server + built-in node:sqlite + static HTML/CSS/ES modules. Keep core install/start simple and runnable; do not introduce a heavy framework just to scaffold. Native MCP HTTP adapter is preferable to spawning a new PowerShell for every event poll. Existing tools/agentdock-rpc.ps1 and artifacts/bootstrap/agentdock_tools.json provide a working local auth/transport reference and discovered ACP schemas. Credentials may be decrypted only into process memory; never ship them to the browser or files. New ACP sessions use an empty project-owned narration workspace, read-only mode, no additional directories; narration is instructed NOT to call tools, and unexpected tool/permission events are rejected/cancelled. This is still a local trusted-user prototype, not a proven hostile multi-tenant sandbox. Document this explicitly.

Two speed design: a small low-frequency Story Brain (on opening/checkpoint, default every 8 turns or meaningful milestone) makes a mini plan from canon, never precommits outcomes; a fast Narrator makes the current scene + structured proposals/choices in ONE call. Deterministic reducer validates and applies allowed deltas atomically. Only conditional, bounded repair when necessary, no unconditional multi-agent chain per turn. Keep context compact, from state + relevant facts + recent prose, not entire transcript. All model IDs/configurations must come from real advertised capabilities; record actual model. An API/no-tools adapter may be added later, not required to expose a paid new provider now.

## API agreement (backend and UI parallel ownership)
Static entry public/index.html. Server default http://127.0.0.1:4317. All API JSON is UTF-8.
- GET /api/health -> {ok, version, provider:{name,model,status,warning?}}.
- GET /api/worlds -> {worlds:[{id,title,subtitle,description,powers:[{id,name,description}]}]}.
- GET /api/games -> {games:[{id,name,title,updatedAt,turnNumber,realm?}]}.
- POST /api/games body {name,powerId,worldId} -> {game}. Creates durable seed, does NOT pretend seed text is live model output.
- GET /api/games/:id -> {game}.
- POST /api/games/:id/turns body {action,expectedVersion,requestId} -> server-sent events over POST fetch: event: stage data:{name,status?,elapsedMs}; event: text data:{delta}; event: complete data:{game,turn,metrics}; event: error data:{message,code,retryable,traceId?}. UI creates a game and then sends action '开始我的故事' to get live opening. Stream real text, not a simulated typewriter after full response. Preview text is provisional until commit; complete replaces it with the accepted narrative if repaired.
- POST /api/games/:id/cancel -> cancel ONLY this game's in-flight generation, preserve state; return {cancelled}.
- GET /api/games/:id/export?format=md|txt -> downloadable UTF-8 novel with grouped chapters.
- GET /api/games/:id/metrics -> {turns,summary}, all measured fields can be displayed raw when extra detail exists.

Game object: {id,name,title,version,createdAt,updatedAt,state,turns,chapters?}. State visible interface: {realm:{name,rank,progress},location,coins,inventory:[{id?,name,description?,qty?}],relationships:[{id?,name,role?,attitude?}],goal,turnNumber,power:{id,name,description},facts?:[],promises?:[]}. Turn: {id,index,action,narrative,choices:[{id,label}],changes:[string],createdAt,chapterIndex,traceId}. Additional fields allowed; UI use sensible guards. Keep secret future story plans out of the browser game response. Error status codes should be correct before SSE begins; handle SSE error frames too.
