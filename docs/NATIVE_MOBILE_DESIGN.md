# Native Mobile：回合交接与阅读空间

当前为 `0.9.0-android.3`（9003），是在已有原生工程与v0.9同一后端上的迭代，不是重做客户端。实际测试结果见 `NATIVE_MOBILE_TESTS.md` 与本轮physical报告。JingYou只读参考交互工程，不复制健康dashboard视觉。

## 阅读页的阶段

**行动输入 → 立即接收 → 正文 → 结果确认 → 下一轮行动。**

发送时先同步pending、轻量反馈，旧建议与输入向下收起淡出，IME自然退出；不是留着一整块失效表单。首段前以小范围三个呼吸点持续表示等待，不使用假百分比、隐藏推理、大spinner或整屏shimmer。真实正文出现后等待元素退场，正文占据主空间。

服务器 `narrative_end` 只表示暂定正文写完，不表示结构化结果/修复/存档已经完成。9003在这个边界自动出现**下一步草稿输入**，无需多点一次按钮；发送仍禁用，旧建议不再出现。只在输入仍等于刚提交的动作时清空它，后写草稿不被删除。

**草稿阶段与正式就绪使用同一个Native TextField实例**。当后台确认完成，输入法光标、selection和composition不应被销毁重建；新的建议/发送权限自然进入，不抢焦点、不自动发送。回合控制返回的触觉只给一次；普通state事实不轰炸奖励。必要的结果确认/校正也有低干扰动态反馈，不能又变成另一块死loading文案。

UI允许提前编辑≠允许提前提交。`complete`仍是唯一正式Canon成功边界，error/取消/版本前进都回读原服务权威。修复可能替换暂定正文；不在客户端私自改小说或强行把未确认状态当奖励。

## 正文、锚点与键盘

历史段落key为gameId/turnIndex/paragraphIndex，流式新增只更新当前暂定文本；正式完成对齐同一段落键。跟随模式在新文本和viewport变化后按真实系统帧滚到末尾；手指主动向上读历史立即关闭自动跟随，回到最新是显式动作。状态sheet、输入坞和IME的尺寸变化不得夺回已关闭的跟随。

正文最大680dp，窄手机按可用宽度；五档字号遵守系统缩放，不把全局fontScale关掉。TextFieldValue保留composition，500字API约束不变；imePadding只在正确层消费，紧凑横屏收起非必要chrome并缩减输入行数，发送保持可见。

本轮有真实Gboard九键按键与“你好”候选提交、键盘/输入框边界观察、系统IME返回、历史/最新与后台草稿恢复，不只是Compose performTextInput。具体布局是否适合所有OEM、字号、Samsung Keyboard和长时间输入仍需实际检查。

## 阅读chrome与可点击性

顶栏由轻量返回、世界/当前位置、**带图形与“状态”文字的描边-tonal胶囊按钮**、设置圆钮组成。状态不再和行动输入挤在底部。返回图形按语义适配RTL，不能把全部图标盲目镜像。

书卡、suggestion、天赋卡、状态分类、设置入口、停止/取消和重试都通过surface层级、边界、对比、触摸面积、原生ripple与系统触觉显示可操作性。Retry有明确文字，不依赖一个陌生小图标。发送为输入区域中的显式主按钮；disabled必须与可点状态有区别。

亮色是纸/墨与克制金色，暗色分别定义深墨背景和surface，不是简单白变黑。内容优先，不叠多层低对比玻璃、不堆发光HUD，不复制Web DOM布局。

## 状态是有分类的角色空间

状态采用大sheet，分类在窄手机**两排三列全部可见**，宽屏可一排六项。先前横向标签把末尾机会/筹码藏起来的问题已经被真实设备观察后修正。

| 分类 | 服务端数据与玩家问题 |
| --- | --- |
| 角色 | 当前realm、benchmark、unlock、位置、目标、下一真实境界：我是什么水平？ |
| 能力 | power/capabilities，去掉相同能力重复呈现：我会什么？ |
| 物品/资产 | inventory、货币等已拥有资源：我有什么？ |
| 人物/关系 | relationships角色与态度：谁会影响我？ |
| 长期筹码 | active progression.leverage：关系、身份、入口、资产，不重新解释成技能 |
| 机会 | open opportunities和近期明确完成项：什么值得争取？ |

显示普通语言标题、说明和作用，不直接抛schema名。这里是服务器状态的展示，不是另建成长模型或评分器。

## 书架是书，不是回合

实际后端 `/api/games` 本来就是一条记录对应一个长期存档；本次改的是原生信息权重，不发明book↔chapter数据库。每张卡以书名/世界/主角/境界为主，回合数与更新时间为次，整体可点且有明确“继续”。进入书后才阅读连续历史。

可展示的世界名/当前方向只来自服务器书架或已缓存的同一game快照；没有为每次书架加载遍历下载所有历史，也没有本地第二个存档目录。

## 五语与可访问性

zh/en/fr/es/ar共290个资源键。切换UI语言不改写已提交历史；历史正文继续按该回合语言排版，Arabic界面中的中文旧故事仍保持适当内容方向。Native系统返回、状态分类和输入锚点须在RTL下可理解。

大字号优先换行与自适应，按钮有原生语义和至少适当触摸区域。所有主要Native控制暴露稳定testTag，Modal单独窗口也设置资源ID导出；这是让实际测试能找对真实控制，不是伪造静态fixture。

## 体验结论的边界

真实APK、触摸、SSE、设备截图与录屏已经存在，不能再称“只有工程骨架”。但自动触摸与系统振动调用不能证明人的手感，截图不能证明半小时阅读不累，渲染帧近似也不是显示器光子时间。120Hz主观观感、长期疲劳和OEM特例保留为需要用户复核，不宣称全面达到JingYou的所有完成度。
